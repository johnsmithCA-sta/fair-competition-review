# 公平竞争审查（政策措施）

把一份政策草案，变成一份**每条风险都能回溯到法条原文**的审查报告和《公平竞争审查表》。

## 定位

对拟出台的**政策措施**逐条扫描，筛查《公平竞争审查条例》禁止的排除、限制竞争内容，按「条款位置 / 原文摘录 / 违反标准 / 法条依据 / 风险等级 / 修改建议」产出结构化审查报告，并生成官方通用格式的《公平竞争审查表》。

审查对象是**政策措施**——政府规章、规范性文件及其他涉及经营者经济活动的政策措施的草案，不是企业营销文案、合同或招投标文件。输出为**审查工作辅助参考**，不构成法律意见，不替代起草单位审查岗与市场监管部门的会审意见。

## 何时用（适用 / 不适用）

**用它**

- 政策草案要发文，需要先过一遍公平竞争审查，或出具《公平竞争审查表》随文附卷。
- 政策已写好，想知道「有没有排除、限制竞争的内容」，或某几条被质疑、想确认依据与改法。
- 存量政策的清理与修订：判断哪些条款应废止、哪些改一改可以留。

**不用它**

- 反不正当竞争执法案件办理、经营者集中申报。
- 企业自身的竞争合规自检——本技能站在审查主体视角，不替经营者做合规体检。
- 招投标文件、政府采购文件的合规审查（另有专门技能）。

## Goal

产出两份文件到用户工作目录：

1. **`公平竞争审查报告_<文件名>.md`** —— 六段固定结构：审查范围判定 / 风险条款清单 / 例外情形评估 / 审查结论建议 / 法条依据索引 / 免责声明。
2. **`公平竞争审查表_<文件名>.md`** —— 官方通用格式，四类逐项「是 / 否」，结论栏**留待审查人员人工确认**；用户要 docx 时可另行导出。

**完成判据**：风险清单里的每一条都有可点击的原文链接，或明确标注了降级来源；给不出来源的条款不写进结论。

## Inputs

- **必填**：政策措施文本——粘贴、上传 docx / txt / md，或给出本地文件路径。
- **可选**：适用地域（决定是否叠加地方细则）、是否征求意见稿（影响建议措辞）、是否要导出 docx。

## 依赖

- Python 3.8+，仅标准库（`zipfile` / `re` / `html` / `argparse` / `json`），无第三方包。
- 法条原文与链接核验需要北大法宝检索工具；不可用时按 `references/pkulaw-mapping.md` 的降级链回落，不阻断审查。

## Constraints

- **不替代法定审查主体**：报告是辅助材料，任何一栏都不得写成「审查通过」的最终结论。
- **法条来源可溯**：条文一律标「法规全称 + 条号 + 原文链接」；**禁止凭记忆引用条号**；取不到原文就标「以官网原件为准」。
- **预筛只是定位助手**：关键词命中不构成违规，零命中也不构成无风险，必须逐条语义核对。
- **保密**：出台前需保密的政策文本，提示用户本地化处理，原文不外传。
- **时效**：报告中标注「适用规则版本日期」；对已被替代的历史文件明确标注其失效状态。
- **逃逸条款**：当本技能的 MUST / NEVER 与用户明确意图冲突、或与其他更高优先级指令冲突时，优先保障用户数据与意图，并显式说明偏离了哪一条及原因——不得静默偏离。

## Steps

### 一、输入与范围判定

1. 取正文：优先读用户粘贴的文本；docx / txt / md 用提取脚本。
   ```bash
   python3 scripts/extract_text.py <文件> --out policy.txt
   ```
2. 确认**适用地域**——国家规则必用，再问是否叠加某地地方细则。
3. 按《条例》第 2 条 +《实施办法》第 2 条判定是否属于「涉及经营者经济活动」的政策措施。
4. 不属于 → 出具《不适用说明》、**写明理由**后停止；属于 → 进入第二步。政策措施恰无涉企内容时可不出具报告，但「认为不属于」的理由必须留档备查。

### 二、四类标准逐条扫描

1. 关键词预筛，拿到疑似位置清单：
   ```bash
   python3 scripts/scan_rules.py policy.txt --format md --out prescreen.md
   ```
2. **必须对全文逐条做语义核对**——预筛只提速定位，禁止用关键词命中直接定性。
3. 重点复核三类易漏项：① 以「奖励 / 补助 / 补贴 / 支持」泛词包装的财政优惠；② 以「经认定 / 评审 / 白名单 / 一事一议」变相确定受益对象；③ 以「注册地迁入、本地纳税、本地采购」为条件。
4. 每条风险先答三个前置问题——**是否涉企 / 是否给予特定经营者 / 内外地是否同等**——再定级。
5. 形成记录：条款位置｜原文摘录｜违反标准编号（条例第 X 条 ＋ 实施办法第 Y 条）｜风险等级｜修改建议。

66 项完整清单、判别要旨与风险分级见 `references/review-standards.md`。

### 三、法条依据核验与溯源

对每条「明显违反 / 疑似」风险，取条文原文与可点击链接：

1. 用**带文号的精确法规名**调用 `get_law_item_content(title=..., tiao_num=...)`，或用 `get_article` 按中文条号取。
2. **核对返回值**——返回的 `Title` / `DocumentNO` 与目标法规不一致即视为落空，换精确名称重试或降级。用简称调用会串到名称相近的其他法规上。
3. 单次 ≤10 条；仅用于核验来源与生成链接，不循环批量抽取拼接数据集。
4. 每条依据按三级标注：**法规全称 + 条号 + 原文链接**，链接原样引用工具返回值。
5. 未收录的（如部分地方细则）→ 回落政府官网或本地法规依据文件，并注明来源；**不编造链接**。

调用方式、标准 → 条号映射与降级链见 `references/pkulaw-mapping.md`。

### 四、例外情形判断

对确拟保留的风险条款，逐项判断《条例》第 12 条例外：四项情形 + 三项要件（不可或缺 / 不会严重限制竞争 / 明确期限）+「无对公平竞争影响更小的替代方案」。**例外不是自动豁免**，须在审查表「个别说明」中论证并明确实施期限。

### 五、输出

按 `references/review-form-template.md` 生成审查表；报告按下列固定结构：

```markdown
# 公平竞争审查报告：《<政策措施名称>》
> 审查日期 | 审查对象 | 适用规则版本 | 审查方式（AI 辅助 + 人工复核）

## 一、审查范围判定
[适用 / 不适用的结论与依据]

## 二、风险条款清单（按严重度排序）
> 来源标注：法宝 / 法规依据文件 / 政府官网；任一降级须注明。
| 条款位置 | 原文摘录 | 违反标准 | 法条依据(含链接) | 风险等级 | 修改建议 |

## 三、例外情形评估
[是否适用第 12 条例外，三要件逐项论证]

## 四、审查结论建议
[通过 / 修改后通过 / 不予通过 + 理由]

## 五、法条依据索引
[法规 × 条号 × 原文链接 汇总表]

## 六、免责声明
本报告为 AI 辅助生成的审查工作参考，不构成法律意见；正式审查结论由起草单位按《条例》
第 13—14 条程序作出，拟由县级以上人民政府出台或提请审议的，还须市场监管部门会同审查。
```

## 决策路径

- 文本**不属于**「涉及经营者经济活动」→ 出《不适用说明》并停止，不进扫描。
- 某条款**确要保留** → 走第四步例外论证，不直接删出清单。
- 法宝**未收录**该法规 → 走降级链并注明来源，不阻断其余条款。

## Verification Checklist

- [ ] 范围判定结论写明了依据（《条例》第 2 条 /《实施办法》第 2 条）
- [ ] 全文逐条语义核对过；预筛零命中的区域也已复核
- [ ] 每条风险都有标准编号 + 风险等级 + 修改建议
- [ ] 每条「明显违反 / 疑似」都有可点击链接或明确的降级来源
- [ ] 审查表结论栏保持「留待人工确认」，未写成最终结论
- [ ] 报告标注了适用规则版本日期与免责声明

## 使用示例

> 用户："帮我审一下这份《XX 市促进新能源汽车产业发展若干措施（征求意见稿）》"

1. 提取正文，判定属「产业发展 + 财政补贴 + 市场准入」类政策措施，须审查。
2. 预筛 + 全文语义核对，标出「对本市销售的新能源汽车给予购置补贴」「优先支持本地企业申报」等条款。
3. 逐条挂《条例》第 10 条第（二）项等标准，取原文与链接。
4. 判断是否适用第 12 条例外；不适用则列入必改。
5. 输出审查报告与审查表，结论写「修改后出台」。

> 用户上传《XX 区招商引资工作指引》，问"要不要做公平竞争审查"

招商引资属《条例》列举的审查领域 → 判定属于审查范围，说明理由并询问是否立即进入逐条扫描。

## 常见错误

- **把预筛「零命中」当成「无风险」** → 预筛召回有限，零命中一律标「需人工确认」。
- **用简称调法宝工具** → 会串到名称相近的其他法规，必须用带文号的精确名称并核对返回值。
- **结论栏直接写「审查通过」** → 法定审查主体是起草单位与市场监管部门，技能只给建议。
- **凭记忆写条号** → 一律取原文核验；取不到就标来源缺失，不写进结论。
